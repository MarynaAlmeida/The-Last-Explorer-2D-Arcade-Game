\section{Findings}
What was learned about writing and running the tests is how significant it is in breaking down code. This is regarding it not being a simple process, but always continuously modified to maintain the quality of the code is successful. Especially when going through parts such as unit testing ensuring the whole class can operate with other classes with integration testing of the interactions. Overall it is essential to always write tests as it can find the presence of bugs that may not have been captured prior. Changes made to the production code resulted in two common ways found throughout the process. The first was adding a get and set method for a class. It was derived from observing during the testing and warnings given for the class. The second was the a null case not being covered. An example is with a switch statement that had a default case for false which could not be reached, so the alternative was to add a if condition before of a null case. There was noticeable change in the quality of the production code and finding bugs to fix. This can be attributed to assertions which helped solve many incorrect expected and actual number cases. An instance includes the testing in static enemy which needed its on collision method to be corrected to having damage inflict the hearts through the difference and not decrementing.

Through writing and running our tests, we were able to identify various methods, variables and branches that were seemingly unused or skipped during our coding phase.
Additionally, while writing and running our tests for the chest class, we identified a variable inside of the chest class that followed the same behaviour as the "collected" boolean. As a result, whenever these two variables were used together, the second branch involving the secondary variable would never run. As a result, we removed the second variable and all associated methods, which allowed us to achieve 100\% line and branch coverage for that class. All other reward classes did not have any issues.
Furthermore, we were able to reveal a bug in our compilation of JavaDoc comments, that being that we did not add the plugin for JavaDoc comments. By revealing this bug, we were able to improve the quality of our code by now being able to create a JavaDoc index file, which explains each class and method.
