\section{Refactoring Performed in My Own Code}

\begin{enumerate}
    \item \textbf{Unused Variable and Confusing Variable Name} \\
    private Game game / private Game g was only being set in the constructor and not used anywhere else. Additionally, private Game g and the parameter in paintComponent(Graphics g) shared the same variable name. To resolve this, the unused variable private Game game was removed from the LosingByHearts and HomePage classes, all affected classes were updated, and the game parameter was removed from the LosingByHearts constructor.

    \item \textbf{HomePage: Unused Imports} \\
    Some imports such as game.main and game.entities were not being used. To resolve this, all unused imports were removed.

    \item \textbf{LosingByHearts: Unused Imports, Confusing Comments, and Poor Getter Names} \\
    Some imports were not being used, some comments appeared confusingly at the end of methods and constructors, and getter names getBX, getBY, getBWidth, getBHeight were not descriptive enough. To resolve this, unused imports were removed, misplaced comments were deleted, and the getter names were renamed to getButtonX, getButtonY, getButtonH, and getButtonW.

    \item \textbf{WinningView: Vague Comments} \\
    Some comments lacked sufficient explanation, for example just saying "pixels" with no context. To resolve this, comments were updated to be more descriptive, for example changing "pixels" to "converting grid to pixels format."

    \item \textbf{GameView: Class Too Large Due to Tutorial Logic} \\
    Having the tutorial implementation inside GameView made the class too large and caused it to diverge from its purpose of handling game world visuals. A new class TutorialView was created with getters and a paintTutorial() method. GameView was updated to use the public getters from TutorialView, and the parameters of the GameInput class were updated accordingly.

    \item \textbf{GameView: Minor Code Smells} \\
    In drawBarriers and drawVisibleBarriers, case Empty: break was used where default: break would be more appropriate. Line 579 contained commented-out code that needed to be removed, and gameLoop and tileSize were not declared as private. To resolve this, gameLoop and tileSize were made private, a getter was added for tileSize in GameView, affected classes were updated, the last case in both barrier methods was changed to a default case, and the commented-out code on line 579 was deleted.
\end{enumerate}
