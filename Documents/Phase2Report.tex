\section{Overall Game Plan}
The phase 2 game plan was to begin with creating method declarations inside of each class. By doing this, we were able to utilize abstraction of these classes to create our own methods without worrying about how other classes worked in the background. Afterwards, our plan was to create the logic for and between these classes. As a result, we were able to implement the Java Swing portion of the project with ease, as all of our methods and logic were already there. Furthermore, our plan was to proactively bug-fix while implementing the Java Swing animations, as we were now able to visually see where rewards, entities and barriers were, and were able to see how the logic of these classes changed the panels of our game, and fix it if it was not desirable.

\section{Management Process}
The phase 2 management process was noted to be split into two parts. The first part was figuring out among group members which parts they would like to do in the coding implementation. It was considered to be finalized by the TA meeting day. The second part was executing tasks by each group member a few days prior to the final deadline. This allowed people to work on the phase 2 report which required less time. Leading to how the division of roles and responsibilities was done which was conducted towards an even split. Where each person in the group decide which parts to code through the UML diagram to select that would result in even work to distribute based on splitting total files needed. The same rules applied with the report also and larger coding structures was allowed to have collaboration among group members for efficiency of the time constraint. 

\section{Biggest Challenges Faced}
One of the first major challenges faced for the group was managing time. It can be difficult to find time to communicate in meetings or complete tasks among five people whether it was due to school, work, and other outside life components. The second challenge was solving group issues which were unexpected. An example includes missing members in meetings for role dispersion where it was resolved for the person to receiving the remaining tasks left by default. A third challenge was even work distribution among each individual in the group. It was the goal to strive for evenly split tasks, but despite conducting this method it may still lead a few people having a higher workload within their role compared to others that needed to be compromised. The last major challenge was understanding the direction of project. It is not a simple task to start from the scratch especially for phase two, so managing how to start and develop work was a key to success in order for completion.
